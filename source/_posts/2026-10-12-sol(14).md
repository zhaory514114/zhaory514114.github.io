## 思路

由于每次操作最多只能使一个三元组的元素和增加 $1$，因此可以考虑二分答案，判断能否在 $k$ 次操作内使所有三元组的元素和都不小于 $x$。

对于每个三元组，设当前元素和为 $sum=a+b+c$。

如果 $sum\ge x$，则不需要进行任何操作。

否则，需要考虑如何以最少的操作次数使其元素和达到 $x$。

### 存在可以直接使元素和增加 $1$ 的操作。

根据三种操作的定义，只要满足 $a>b$、$a>c$ 或 $b>c$ 中的任意一个条件，就可以直接使元素和增加 $1$。

并且，这种操作可以一直重复进行。例如，当 $a>b$ 时，可以不断执行 $c\gets c+1$，由于 $a,b$ 不变，所以 $a>b$ 始终成立。

因此，这种情况下需要的操作次数为 $s=x-sum$。

### 无法直接使元素和增加。

此时必然满足 $a\le b\le c$。

如果 $a=b=c$，那么所有操作产生的变化量都为 $0$，无论执行多少次操作，都无法改变元素和。因此，只要当前元素和小于 $x$，就不可能满足要求。

否则，可以先通过若干次使元素和减少的操作，创造出能够持续增加元素和的条件。

有两种方法：

1. 当 $a<b$，需要 $b-a+1$ 次操作。
2. 当 $a<c$，需要 $c-b+1$ 次操作。

取两种可行方案中操作次数的最小值，记为 $y$。

经过 $y$ 次操作后，元素和变为 $sum-y$，并且此后可以通过重复一种操作，使元素和每次增加 $1$。

因此，还需要 $x-(sum-y)$ 次操作，总操作次数为：

$$
s=y+x-(sum-y)=x-sum+2y
$$

对于每个三元组，分别计算其达到 $x$ 所需的最少操作次数。如果总次数不超过 $k$，则说明 $x$ 可行，否则不可行。

通过二分查找最大可行值。

二分下界取所有三元组初始元素和的最小值，上界取 $\min(a_i+b_i+c_i+k)$，因为任意一个三元组的元素和最多只能增加 $k$。

### 代码

```
#include <bits/stdc++.h>
#define rep(i,j,k) for (int i = (j); i <= (k); i ++)
#define per(i,j,k) for (int i = (j); i >= (k); i --)
#define uint unsigned int
#define ll long long
#define ull unsigned long long
#define db double
#define ldb long double
#define mkp make_pair
#define eb emplace_back
#define e_ emplace
#define ls (p << 1)
#define rs (p << 1 | 1)
//#define int ll
using namespace std;
const int N = 2e5 + 5;
const int INF = 0x3f3f3f3f;
const ll LINF = 4e18;
struct xx {
    ll a, b, c;
};
int n;
ll k;
xx e[N];

bool check (ll x) {
    ll used = 0;
    rep (i, 0, n - 1) {
        ll a = e[i].a, b = e[i].b, c = e[i].c, sum = a + b + c;
        if (sum >= x) continue;
        ll s;
        if (a > b || a > c || b > c) s = x - sum;
        else {
            if (a == c) return false;
            ll y = LINF;
            if (a < c) y = min (y, b - a + 1);
            if (a < b) y = min (y, c - b + 1);
            s = x - sum + 2 * y;
        }
        if (s > k - used) return false;
        used += s;
    }
    return true;
}

signed main () {
    ios::sync_with_stdio (0);
    cin.tie (0);
    int T;
    cin >> T;
    while (T --) {
        cin >> n >> k;
        ll l = LINF, r = LINF;
        rep (i, 0, n - 1) {
            cin >> e[i].a >> e[i].b >> e[i].c;
            ll sum = e[i].a + e[i].b + e[i].c;
            l = min (l, sum);
            r = min (r, sum + k);
        }
        while (l < r) {
            ll mid = l + (r - l + 1) / 2;
            if (check (mid)) l = mid;
            else r = mid - 1;
        }
        cout << l << '\n';
    }
    return 0;
}
```

### 时间复杂度

每次 `check` 需要遍历所有三元组，并进行常数次运算，时间复杂度为 $O(n)$。

二分的答案范围长度不超过 $k$，因此最多进行 $O(\log(k+1))$ 次检查。

单组数据的时间复杂度为 $O(n\log(k+1))$。
